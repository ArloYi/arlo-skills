# 部署接入原则

## 已有项目

优先使用项目已经验证过的部署文档、脚本和平台。日常更新不顺手迁移服务器、目录、账号或网络配置。

## 首次上线

项目没有部署目标时，根据项目类型和用户已有资源选择最简单的可靠方式。只需确认：

- 部署到哪里；
- 如何执行构建和发布；
- 发布哪些内容；
- 上线后检查哪些地址和功能；
- 失败后如何恢复。

可使用服务器上传、托管平台、CI/CD、容器、对象存储或其他可验证方法。自托管网站可以使用版本目录和原子切换，但不是硬性要求。

## 域名和基础设施

首次绑定域名时可完成 DNS 和 HTTPS。修改 DNS、证书、权限、数据库、共享服务或付费资源前，先展示准确目标、影响和恢复方式并获得确认。

项目配置只记录非敏感参数。密码、私钥、Token 和 AccessKey 必须留在系统凭证、Secret 服务或受控 CLI 配置中。
