# 公开仓库导出

公开发布不是本机目录镜像，而是从本地工作成果中筛选出的可复用副本。仅在目标仓库为公开仓库时读取本说明。

## 筛选原则

- 保留完成任务所必需且对不同用户成立的流程、判断标准、脚本和模板。
- 删除仅反映某个用户工作习惯、沟通偏好、历史事故或单一项目约定的内容。
- 某条个人经验确有普遍价值时，提炼它防止的风险和可验证结果，以通用规则表达，不保留来源身份。
- 项目配置与公开模板分离；公开模板只使用字段名、占位符和保留示例值。
- 无法确认是否适合公开的内容保持在本地，并在推送前请求确认。

## 必须移除或替换

- 姓名、用户名、邮箱、电话号码、账号 ID、组织内部称呼和个人联系方式。
- 真实产品名、客户名、内部仓库名、业务数据、未公开路线图和历史记录。
- 真实域名、非保留 IP、服务器名、SSH 别名、用户目录、绝对本机路径和生产目录。
- 云资源 ID、区域与拓扑细节、DNS 记录、证书路径、数据库地址和内部接口。
- 密码、私钥、Token、Cookie、环境变量值、含凭证的 URL，以及可能推导出凭证的输出。
- 仅为某个人定制的时间阈值、汇报措辞、工具偏好和操作习惯。

需要展示格式时使用 `<project>`、`<domain>`、`<account>`、`/path/to/project`、`example.com` 或文档保留网段等示例值。

## 推送门槛

1. 从公开仓库的干净工作树开始，只选择本次需要公开的文件。
2. 检查 `git diff` 和 `git diff --cached`，确认没有整目录复制带来的额外文件。
3. 搜索凭证特征、邮箱、绝对用户路径、IP、域名、账号标识和真实项目名；仓库已有秘密扫描工具时一并运行。
4. 阅读 staged 文件的上下文，完成工具无法识别的语义脱敏，尤其是个人习惯和业务事实。
5. 运行 Skill 与仓库校验；只有扫描结果可解释且 staged 内容全部适合公开时才 push。

脱敏后的公开版本可以与本机版本功能等价，但不要求逐字、逐文件或逐目录一致。
